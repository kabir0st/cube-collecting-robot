# Codebase audit — robotics-labs-solutions

Generated on the `all-enabled` branch with the full pipeline (vision +
chase mission + battery + carry-home recovery + lab GOTO/TEST). This
audit documents:

1. **How the runtime is wired together** — what runs in which thread,
   what each thread shares, and how data flows from sensors to motor
   commands.
2. **Subsystem behaviour** — what each module is responsible for and
   what contracts hold at its boundaries.
3. **The mission state machine** — every transition, the side-effect on
   entry/exit, every sub-state machine (SEARCH sweep, APPROACH
   chase/push/grip, CARRY_HOME stuck-recovery, halt-and-localize), and
   the timing assumptions.
4. **Mission scenarios** — walk-throughs of concrete situations the
   robot encounters and the per-tick rationale for its behavior.
5. **Bugs, flawed logic, and races** — findings from a line-by-line read
   of the codebase, with file:line citations.

## How to use this doc

- Start at [architecture.md](architecture.md) for the 10,000-ft picture
  of threads + shared state.
- [state-machine.md](state-machine.md) is the deepest single file in the
  codebase ([src/controller.cpp](../../src/controller.cpp), ~1500 lines)
  and the one most worth understanding before touching mission logic.
  It also documents every sub-state machine (SimpleSearch, APPROACH
  phases, CarryPhase, halt-and-localize).
- [scenarios.md](scenarios.md) walks through concrete situations
  (happy path, vision flicker, box wedged in corner, wall hit during
  carry, persistent stuck, GOTO halt, mid-mission abort, obstacle bias
  during approach). Use it when you want to know *why* the robot did
  what it did, not just *what* state it was in.
- [bugs-and-issues.md](bugs-and-issues.md) is the historical action
  list — every item has a **Fixed:** line citing the change.
