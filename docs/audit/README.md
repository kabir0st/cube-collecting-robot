# Codebase audit — robotics-labs-solutions

Generated on the same branch (`dev`) that just re-enabled the full pipeline
(vision + chase mission + battery). This audit documents:

1. **How the runtime is wired together** — what runs in which thread, what each
   thread shares, and how data flows from sensors to motor commands.
2. **Subsystem behaviour** — what each module is responsible for and what
   contracts hold at its boundaries.
3. **The mission state machine** — every transition, the side-effects on
   entry/exit, and the timing assumptions.
4. **Bugs, flawed logic, and races** — findings from a line-by-line read of
   the codebase, with file:line citations.

## How to use this doc

- Start at [architecture.md](architecture.md) for the 10,000-ft picture.
- [bugs-and-issues.md](bugs-and-issues.md) is the actionable list — that is
  where to look first if you are deciding what to fix.
- [state-machine.md](state-machine.md) is the deepest single file in the
  codebase ([src/controller.cpp](../../src/controller.cpp), ~830 lines) and the
  one most worth understanding before touching mission logic.
